## 3. Landing：完成一次完整的交互整理

### 本轮目标

Landing 不再继续堆叠更多装饰，而是把已经存在的 NewTone、手绘线、引导箭头、视差与 Reader 回程重新组织成一套统一交互语言。

### 最终保留结果

- Landing 整体交互时序重新整理。
- NewTone 标题描画 / 擦除时序经过多轮真机和浏览器反馈调整。
- Landing guide 最终收敛为较短、较直、手绘感明确的箭头。
- guide 采用描画进入、擦除离开的方式，不使用普通淡入淡出来代替手绘逻辑。
- guide 与 NewTone 使用反方向 parallax，形成前后层级，但不做重型 3D 景深场景。
- 两条 NewTone 签名手绘线的形态和出现时机得到修正。
- Reader 返回后不再依赖一个假的 Landing 视觉，中途表现结束后直接进入真正的 live Landing。
- Reader 返回后的 Landing 仍然拥有自己的 live parallax。
- Landing 接管 return state 后，再完成 NewTone redraw、状态反馈、反馈淡出与 guide 重新出现。

### 阶段结论

Landing 当前视为 **Locked**。

本轮之后不应再因为“这里似乎还能优化一点”而重新打开整个视觉系统。

## 4. Reader 首次进入：从设置页变成进入过程

### 原阶段问题

Language / reading mode 虽然功能上能完成选择，但早期形态容易像一个普通 setup/settings page，与 NewTone Reader 本身的连续感不一致。

同时 desktop 与 mobile 的输入条件不同：

- desktop 可以使用 hover + wheel；
- mobile 没有可靠 hover，而且会遇到 sticky hover、touch/pen 输入冲突等问题。

### 本轮完成

- Reader setup / entry interaction 重做。
- language / reading mode 流程重新整理。
- desktop 保留主动确认语义，而不是仅 hover 停留后自动被推进。
- hover、scroll、wheel 的反馈与 Reader 本身向下推进的交互语言对齐。
- touch / pen 输入补齐。
- mobile 避免 sticky hover。
- armed 后的 swipe 逻辑逐步从局部 selector 扩展到更符合真实手势的页面范围，并避免被 Reader 既有输入吞掉。
- 多余 divider 与普通 UI 感较重的元素被删除或收敛。
- 最终方向明确为：Reader entry 是一个连续进入 Reader 的过程，不是独立设置面板。

### 阶段结论

Reader entry 当前视为 **Stable**。

继续施工优先处理具体兼容 bug，不重新设计整套进入流程。

## 6. Reader Return：本轮最重要的交互定案之一

### 要解决的问题

Reader 到正文末端后必须有“回到 Landing”的能力，但一个普通固定按钮会破坏 Reader 的轻 UI / 非网页控件感；单次输入立即离开又容易误触。

同时需要让 desktop mouse/wheel 与 mobile touch/pen/swipe 都拥有对应语义。

### 最终完成的行为

正文末端：

`return cue appears`

→ 第一次对应输入：

`armed`

→ 第二次对应输入：

`confirm`

→ 两条手绘 cue：

`reverse retract`

→ retract 完成：

`navigate`

→ 进入：

`live Landing`

### 本轮解决的具体问题

- mobile final node 能正确出现返回入口；
- safe area 处理；
- 横屏布局；
- armed swipe 不再被 Reader 原输入逻辑吞掉；
- mobile sticky hover；
- return control 出屏；
- desktop / mobile 的确认语义对齐；
- cue 的出现和收回与导航顺序明确。

### 阶段结论

Reader Return 当前为 **Locked**。

除非出现可复现 bug，不再继续调整 mobile return。

## 7. Reader → Landing：取消重型中间转场

### 本轮早期方向

曾经尝试让 Reader 与 Landing 之间由一个更明显的 global transition / overlay 承担视觉交接，包括 overlay NewTone、paper layer、不同 guide/Logo 状态之间的衔接。

### 最终发现的问题

这条路线不断增加状态和视觉责任：

- Reader 要知道 Landing 长什么样；
- overlay 又在模拟一个 Landing；
- 真正 Landing 在后方等待接管；
- 多个 NewTone / Logo 状态容易同时出现或产生接力感；
- return 本来应该很轻，却逐渐变成一个独立大转场。

### 最终收敛

旧的显式重型 global transition 方向基本取消。

当前责任链：

Reader return

→ cue retract

→ 导航

→ live Landing

→ NewTone redraw

→ return state feedback

→ feedback fade

→ Landing guide

其中 Reader 只完成 Reader 自己的结束动作，Landing 负责 Landing 自己的视觉。

### 阶段结论

Reader → Landing handoff 当前为 **Locked**。

不要重新引入双 Logo 接力或重型中间 transition。

## 8. Analytics v2：完成端到端 observability

### 本轮目标

不是无限增加埋点，而是让首章真实用户路径可以被可靠回答：

- 用户有没有进入 Reader；
- 进入后是否开始阅读；
- 到了哪里；
- 停留多久；
- 是否返回；
- 返回后是否继续；
- refresh / hidden / session end 是否会让 dwell 被错误截断。

### 本轮新增 / 完善

- `reader_entry_requested`
- `content_status`
- `page_entered`
- `chapter_entered`
- `beat_dwell`
- `chapter_completed`
- Reader toolbar `language_selected`
- Reader toolbar `mode_selected`
- `browser_back`
- visibility dwell
- `session_end` cumulative dwell

### 真实 staging 链路验证

一轮真实 session：

- 88 events；
- sequence 1 → 88；
- 无 duplicate sequence。

验证链路：

Landing

→ `reader_entry_requested`

→ language

→ mode

→ `reading_started`

→ `chapter_entered`

→ `page_entered`

→ `beat_reached`

→ `beat_dwell`

→ 25%

→ 50%

→ `reader_return`

→ Landing

→ `reader_entry_requested: continue`

→ 从原位置继续。

### Dwell 修复

曾出现 refresh 后 session dwell 被早期 `session_end` 截断的问题。

最终计算方向改为：

**最后一个 cumulative checkpoint + checkpoint 后新增 visible dwell**

本轮真实验证最终 dwell：

`70.840s`

### 阶段结论

Analytics v2 当前视为 **Locked / Stable**。

下一阶段不继续把埋点扩张成 mousemove / hover / wheel 微行为监控。

## 11. 这一轮明确结束了什么

本轮结束后，不再把以下内容视作“开放设计题”：

- Landing 箭头应该长什么样；
- Landing 是否需要重新做 parallax；
- Reader return 要不要加一个普通按钮；
- Reader return 是否应该单次输入直接跳走；
- Reader → Landing 是否需要一个重型双 Logo transition；
- Reader progress 是否应该做成可交互控件；
- Analytics 是否应该继续为了细而无限增加微行为埋点。

这些方向以后当然可以在产品发生结构性变化时重新打开，但不能以“顺手优化”为理由重新开始。
