## 2. 本阶段完成的主题

### 2.1 Landing 从单点提示扩展为持续入口表面

- 入口流程改为持续挂载的 Entry Surface，避免每个步骤重新建立一套页面表面。
- Landing 支持阅读入口与 Updates 入口，并为进入、返回、方向提示、语言切换保留同一套状态生命周期。
- 多轮箭头、ring、文字和退出时序提交是为了解决同一入口链的可见性、方向和衔接，不应逐项当作新的 release feature。
- 已被后续替换的 circle/ring 或复杂 guide 实验属于历史，不自动代表当前产品方向。

### 2.2 统一语言、阅读模式与 Reader 入口控制

- Language selector、entry button、entry text flip 和阅读进入流程逐步抽为共享组件/时间线。
- Desktop 保留 hover 指示 + 明确 downward wheel 的确认语义；touch/pen 维持先选择/armed、再确认推进的语义。
- 本阶段的目标不是增加传统设置页，而是让选择、转场和进入 Reader 保持为一条连续体验。

### 2.3 Reader 完成、返回与 Landing 交接

- Reader completion prompt、return control、return mask/fill、手势仲裁与 shared SVG surface 都经过重构。
- Reader return 不应抢走正常阅读输入；完成阅读和返回 Landing 仍是明确的、可中断的状态链。
- Landing 应由真实的 live Landing 接管后续视觉与视差，而不是让 transition overlay 伪造第二个 Landing。

### 2.4 Analytics v2 保留为运行支持层

- analytics observability migration、summary replay safety、dwell checkpoint 和 contract tests 已加入 staging。
- 目的仅是可靠回答真实阅读路径和停留行为，不把 analytics failure 变成产品阻断。

### 2.5 Updates 成为真实的双语公告表面

- Updates 不再是占位层：它使用真实的中英文 DOM 内容、时间线、日期展开/收起和共享的返回入口。
- 页面与 Landing 使用同一 `720ms` 表面转场时长，避免切换时遮挡；NewTone 手写动画仍保持独立。
- 公共 PageShell 另设交互保护，处理移动端点击高亮、长按菜单、文本选择及常见复制快捷键，不修改 Reader 或既有 Landing 的业务输入链。

## 3. Reader handoff 时间线

提交链：`e4900be` → `4165410` → `741fb19` → `2e937b2` → `b8afdd5`。

最终问题不是单个 CSS 动画速度，而是两套固定等待把视觉完成、Reader readiness 和返回收回拆开了：

- 进入 Reader：原 `MIN_READER_MS` / `RESUME_READER_MS` 会在视觉已完成后制造额外等待。
- 返回 Landing：原状态等待、状态淡出、标题收回顺序会形成明显停留后再快速收回。

最终实现：

```text
Reader ready + transition visual complete
→ transition leaving
→ fade complete
→ idle / Reader visible

Landing return status fade + return-specific title retract (640ms)
→ Landing guide may resume only after handoff
```

实现边界：只改 entry/transition/Landing title handoff 的必要链路与契约测试；不改 Reader 内容、完成边界、其他入口路由或全局标题收回时长。

施工记录中的验证：浏览器观察到 title revealed 后不再经历固定平台期，Reader 在淡出期间保持挂载；返回 Landing 的标题连续约 640ms 收回。33 个测试文件 / 130 个测试、lint、typecheck/build、diff-check 均通过。
