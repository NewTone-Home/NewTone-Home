# 玩家账号系统候选：实现与验收边界

基线：`staging` 的 `998d6bd45e6744dc67d196891cb8108d20e0daab`。
独立分支：`feat/player-account-save-foundation-20261107`。
用户已选择邮箱验证码和每账号三个存档槽。没有合并未验收的联网控制分支。

这是本地候选，不是已上线、已完成全部验收的账号系统。未推送、部署、执行远端 SQL、配置凭据、发送真实验证码或登录真实玩家账号。

## 已实现的候选路径

- 中英账号入口、邮箱验证码输入、Google 登录入口、三槽列表、新建和选槽、退出及游客入口。
- 专用玩家 Supabase 客户端和 PKCE，独立于管理员客户端；配置缺失时不创建客户端。正式入口有账号开关和云端就绪开关，默认关闭。
- 账号/槽独立 Storage。每次读写绑定当前会话，不从别人的槽或游客原始键回退。槽数作为独立策略维护。
- 协调器负责卸载旧游戏、撤销旧 Storage、等待旧写锁释放，再打开新槽。旧异步准备/退休操作不能在退出后继续写入。
- 注册认领通过云端确认目标和原操作后进行，不凭本地没有槽推断“新账号”。原始游客档保留，认领日志阻止退出后另一账号再次认领；新游客使用独立空间。
- 认领和云档首次导入均有持久事务日志、不可见的准备阶段和提交点。准备日志即占用槽位，即使下一步元数据写入失败也不会被抢占。每步写入失败/写后抛错都保留恢复证据。
- 云端客户端、精确请求队列、回执恢复、版本 CAS、首次下载、基线同步。丢失响应后重试原请求，不生成新槽掩盖未知结果。
- 闭合运行时后同步再切槽/退出；运行中可上传只读捕获的快照，默认三十分钟检查点。上传旧快照不会回写较新的本地游戏。
- 会话恢复与明确新登录分开。租约失败/账号更换会撤销本机运行时。默认游客服务也检查认领日志，不能通过关闭账号功能绕回已认领旧档。

## 保留的关键不变量

1. 沿用 `persistent-era-1`、现有 journal、完整 PlayerSave 校验和共享 `WRITER_LOCK`。不搬回旧测试档的游戏状态，不创建第二套玩家保存格式。
2. 云传输包括完整有效 `values` 和恢复标记，不只传 PlayerSave。不会上传旧 `sources`、`archive`、认证信息或分析日志。
3. 不按时间戳覆盖，不把解析失败当作空档，不删除未知格式、原游客字节、事务日志或备份。
4. 完成的认领/导入重试不会把最初快照重新盖到已继续游玩的目标上。
5. localStorage 命名空间是应用隔离，不是加密，不能防御可打开浏览器开发者工具的人。此候选不宣称提供磁盘加密或不可绕过的本机隐私边界。
6. Web Locks 只协调同源合作页面。云端单设备规则必须由服务器会话及 fence 强制，不能只依赖 Supabase 客户端登录状态。

## 仍未完成，不能宣布上线

- SQL 的真实 PostgreSQL/Supabase 执行、RLS/权限/函数与 Auth 触发器测试；尤其旧会话不能接管、恢复、写入，以及新会话生效后的竞态。
- 真实 OTP 收件、邮件模板 `{{ .Token }}`、SMTP 限流/到达率、Google Provider 和准确回调地址的端到端联调。
- 本地/云端真正分歧的手动选择界面、两边备份及选云后的本地替换事务。目前返回明确冲突并保留两份，不自动覆盖。
- 故事开始/结束的精确同步挂点；页面隐藏/关闭只能尽力发送，不能保证退出时网络提交完成。
- 备份恢复、保留容量/删除策略、磁盘空间用尽后的完整产品体验。本候选不擅自自动清理旧记录。
- 本地副本加密、会员权益和支付。
- 与独立联网控制候选合并后的整体验收。没有把该分支中尚未验收的联网行为带进来。

## 验证记录

全部测试使用合成存档、注入的认证/RPC 或新建临时浏览器上下文，没有读取真实玩家存档。

- 修改前基线全量：1580 项，1531 通过，49 失败，25 个失败文件。
- 最后一次定向集成回归：23 个文件、343 项全部通过；包括账号、OAuth、认领、云导入、恢复及原存档入口/ACK/运行时测试。
- 此轮 `typecheck`、`lint`、生产 `build` 均退出 0。原有 lint 警告及大 chunk 警告未顺手清理。
- 原生 Chrome 的真实 localStorage/Web Locks 验证通过：双标签互斥、保存后重载保留 650 余额、撤销后不能写旧槽。只是存储契约测试，不是线上账号验收。
- 浏览器账号宿主使用临时 Edge 上下文及注入适配器，验证中文、游客按钮、键盘开关、第二槽切换、390px 无横向溢出及未配置 OTP 禁用；实际截图和完整结果在本地 `test-results`。
- 最近一次全量快照：1800 项，1748 通过、52 失败；失败均在原有测试文件，没有账号新增测试失败。按测试标题与修改前日志比对，47 项能直接匹配原失败，其余 5 项位于原场景/路线测试。针对它们保留原断言和超时、仅单 worker 重跑，7 项选中测试通过、17 项未选。此结果不等于全量全绿，也不把重跑冒充首次通过。此后新增的 OAuth 及 SQL 静态测试包含在上面的 343 项定向结果中。
- `npm ci --ignore-scripts` 使用原锁文件，报告 7 个依赖漏洞（2 moderate、5 high）；未自动升级或修改锁文件。

## 上线前顺序

1. 在隔离测试数据库执行并审计 SQL，补齐数据库安全测试，确认注册授予与已有账号行为。
2. 完成真正冲突选择/备份恢复和故事检查点，跑浏览器多账号、多槽、退出、断线和多设备测试。
